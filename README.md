# Orridan website (orridan.net)

Static marketing site for Orridan, built with Vite, React 19, TypeScript and Tailwind CSS 3.
It is uploaded by FTP to Apache shared hosting. There is no Node server in production: the
only server-side code is the PHP contact endpoint in `api/`.

## Quick start

```bash
npm install
npx playwright install chromium   # needed by the build's prerender step (and by e2e)
cp .env.example .env              # then fill in the values (see below)
npm run dev                       # http://localhost:5173
npm run build                     # production build in dist/
```

## Where things live

| What | Where |
|---|---|
| All text, numbers, routes, links, prices, FAQ, legal copy | `src/content.ts` |
| Public settings (keys, URLs) | `.env` (template: `.env.example`) |
| Design concept and section-by-section intent | `DESIGN_BRIEF.md` ("The Engineering Drawing, Alive") |
| Design tokens (colours, type scale, drawing lines, grid) | `src/styles/index.css` (`:root`) and `tailwind.config.ts` |
| Drawing primitives (section tags, dimension lines, callouts, guide grid, drawing strips) | `src/components/Drawing.tsx` |
| Logo, favicons, OG image, fonts | generated by `scripts/generate-brand.ts` into `public/` |
| Pages | `src/pages/` |
| Landing page sections | `src/sections/` |
| Shared components (nav, footer, consent, chatbot, SEO) | `src/components/` |
| Logic with unit tests (pricing, chat matcher, consent, comparison) | `src/lib/` |
| Contact and newsletter endpoint | `public/api/contact.php` |
| Apache rules | `public/.htaccess`, `public/api/.htaccess` |

Never hardcode copy in components: edit `src/content.ts`. Values written as
`[Something to be added]` are placeholders. They are shown as visible text but never used for
`tel:`, `mailto:` or structured data. Social and citation links render only when they have a
real URL.

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Dev server |
| `npm run build` | Brand assets, pricing consistency tests, Vite build, then `postbuild` (per-route HTML with SEO head, prerendered body markup, sitemap.xml, file checks) |
| `npm run check` | typecheck, lint, check:dashes, check:placeholders, unit tests, build, check:links, check:php |
| `npm run check:dashes` | Fails on em dashes, en dashes or prose double hyphens in `src/`, `public/`, `index.html` |
| `npm run check:placeholders` | Lists every unfilled company, social, key and price placeholder (warnings only) |
| `npm run check:links` | Every link in `content.ts`, component source and built HTML resolves |
| `npm run check:php` | `php -l`, subject list sync, and a live run of `contact.php` under PHP's built-in server (skips if PHP is missing) |
| `npm run check:external` | HEAD-checks every external link (needs network) |
| `npm run e2e` | Builds `dist-e2e` with fake keys from `.env.e2e`, runs Playwright in Chromium, Firefox and WebKit at 375, 768 and 1280 px |
| `npm run lighthouse` | Mobile Lighthouse on `/` and `/product` against `dist/` served with compression (reports in `lighthouse/`) |

## .env values

| Key | Value |
|---|---|
| `VITE_SITE_URL` | `https://orridan.net` |
| `VITE_DASHBOARD_URL` | `https://client.orridan.net`. Linked **only from the product page** (header button and nav CTA). `check:links` fails the build check if any other page links to it. |
| `VITE_RECAPTCHA_SITE_KEY` | reCAPTCHA v2 checkbox **site** key (public). Without it, production builds show "Contact form not configured". |
| `VITE_CHAT_PROVIDER` | `none` (default). Any other value is passed to `loadChatProvider()` in `src/lib/optionalScripts.ts`, which only runs after consent. |
| `VITE_STRIPE_LINK_ORGANISATION_MONTHLY` / `_ANNUAL` | Stripe **test-mode** Payment Links |
| `VITE_STRIPE_LINK_TWIN_MONTHLY` / `_ANNUAL` | Stripe **test-mode** Payment Links |
| `VITE_STRIPE_LINK_ENTERPRISE_MONTHLY` / `_ANNUAL` | Not used (Enterprise shows "Contact us"); kept for completeness |

Everything in `.env` ends up in the browser. **Never put a secret key in `.env`.** Rebuild after
changing it. An empty Payment Link renders a disabled button reading "Sandbox checkout not
configured".

### Creating the Stripe test Payment Links

1. In the Stripe Dashboard, switch on **Test mode**.
2. Product catalogue: create "Organisation" with prices $50/month and $480/year, and
   "Twin Management" with $150/month and $1,440/year (USD). These are placeholder prices: confirm
   them with the client and keep `pricing` in `src/content.ts` in sync.
3. Payment Links: create one link per price (four links). Under "After payment" choose
   "Don't show confirmation page" and redirect to `https://orridan.net/checkout/success`.
4. Paste the `https://buy.stripe.com/test_...` URLs into `.env` and rebuild.
5. Test with card `4242 4242 4242 4242`, any future expiry, any CVC.

### Creating the reCAPTCHA keys

1. Go to https://www.google.com/recaptcha/admin/create.
2. Type: **reCAPTCHA v2, "I'm not a robot" Checkbox**. Domains: `orridan.net` (and `www.orridan.net`).
3. Put the **site key** in `.env` (`VITE_RECAPTCHA_SITE_KEY`) and the **secret key** in
   `api/config.php` on the server (`RECAPTCHA_SECRET`). Rebuild.

## Deploying by FTP

1. `npm run check` (all steps must pass), or at least `npm run build`.
2. Connect to the host by FTP/SFTP and open the web root for `orridan.net` (often `public_html/`).
3. Upload the **contents** of `dist/` (not the folder itself), including the hidden
   `.htaccess` and `api/.htaccess`. In FileZilla turn on *Server > Force showing hidden files*.
4. Delete old files in `assets/` that are no longer in `dist/assets/` (file names are hashed).
5. Create `api/config.php` on the server (next section). It is never in `dist/`.
6. Run the post-upload checks below.

### api/config.php (on the server only)

Copy `api/config.example.php` to `api/config.php` on the server and fill in:

```php
define('RECAPTCHA_SECRET', 'your-recaptcha-secret');
define('MAIL_TO', 'inbox@your-company.example');     // where messages arrive
define('MAIL_FROM', 'no-reply@orridan.net');          // fixed sender on the domain
define('ALLOWED_HOSTNAMES', ['orridan.net', 'www.orridan.net']);
define('RATE_LIMIT_SALT', 'a-long-random-string');
```

`config.php` is git-ignored and `api/.htaccess` blocks direct web access to `config*.php`.
`MAIL_FROM` should be an address the host may send for (set SPF/DKIM for orridan.net), or
mail may land in spam. The endpoint needs PHP 7.4+ and `mail()`.

### Post-upload checks (run these yourself)

```bash
curl -I http://orridan.net/                 # expect 301 to https://orridan.net/
curl -I http://www.orridan.net/             # expect 301 to https://... then
curl -I https://www.orridan.net/            # expect 301 to https://orridan.net/
curl -I https://orridan.net/                # expect 200, Cache-Control: no-cache, security headers
curl -I https://orridan.net/product         # expect 200 (served from product.html)
curl -I https://orridan.net/product/        # expect 301 to /product
curl -I https://orridan.net/privacy.html    # expect 301 to /privacy
curl -I https://orridan.net/checkout/success
curl -I https://orridan.net/assets/         # expect 403 or 404 (no directory listing)
curl -I https://orridan.net/missing.js      # expect 404
curl -I https://orridan.net/robots.txt      # expect 200
curl -I https://orridan.net/sitemap.xml     # expect 200
curl -I https://orridan.net/api/config.php  # expect 403
curl -I https://orridan.net/api/config.example.php  # expect 403
curl -i -X GET https://orridan.net/api/contact.php  # expect 405 {"ok":false,"error":"method_not_allowed"}
curl -sI -H "Accept-Encoding: br,gzip" https://orridan.net/ | grep -i content-encoding
curl -sI https://orridan.net/assets/$(ls dist/assets | grep '^index-.*\.js$' | head -1) | grep -i cache-control  # immutable
```

Then: submit the contact form and the newsletter once each and confirm the emails arrive, and
run SEOptimer (or similar) on https://orridan.net/ for canonical, sitemap and robots.

## When the real product page arrives

1. Build the new content (for example `src/sections/product/`) and render it in place of
   `<ProductContentSlot />` in `src/pages/Product.tsx` (see the comment in
   `src/components/ProductContentSlot.tsx`).
2. Set `productPageReady = true` in `src/content.ts`. On the next build `/product` becomes
   `index,follow` and is added to `sitemap.xml`.
3. Update `seo.product` (title and description) if needed, rebuild and upload.

## How it works (for maintainers)

- **Prerendering.** `scripts/postbuild.ts` loads each route of the build in headless Chromium and
  writes the rendered markup into that route's HTML file, so the first paint needs no JavaScript
  and crawlers see the full page. On load, `src/main.tsx` preloads the route's chunks, then React
  renders fresh (no hydration) and swaps the static markup in one commit. Without Chromium
  installed the build still succeeds and prints a warning; pages are then client-rendered.
- **Motion.** CSS for ambient loops and the hero intro (composited layers only, paused offscreen),
  GSAP ScrollTrigger for reveals, count-ups, dimension lines measuring out, the How It Works
  progress line and the footer wordmark fill (always inside `gsap.context()`, loaded on demand),
  framer-motion for menu and dialog fades. `prefers-reduced-motion` turns all of it off.
- **Fonts.** Big Shoulders Display (headlines, outline words), Inter (reading text) and
  JetBrains Mono (labels), all self-hosted from @fontsource. The logo wordmark is pre-drawn
  paths from Sora, so brand files never depend on a runtime font.
- **content-visibility.** Sections below the fold skip rendering until needed. Programmatic
  anchor jumps first render every section (`src/lib/anchorScroll.ts`) so they land exactly.
- **Consent.** `src/lib/consent.ts` stores `{ version, timestamp, categories }` in localStorage.
  Bump `cookieConsent.policyVersion` in `content.ts` to ask everyone again. Optional loaders live
  in `src/lib/optionalScripts.ts` and only run after the matching category is allowed.
- **Pricing.** Every price on the page comes from `getPrice()` in `src/lib/pricing.ts`.
  `src/sections/Pricing.test.tsx` renders the section and fails the build if any two places
  disagree.
- **Truthfulness.** Orridan manages records and metadata. Do not add claims of live data, IoT,
  3D rendering, simulation execution, clients, testimonials or performance figures.
